How It Works
Understanding the detection pipeline from packet to alert
01

Packet Capture

Scapy listens passively on the network interface (e.g. eth0) and captures every incoming and outgoing packet. Each packet is parsed for source IP, destination IP, protocol, ports, and TCP flags, then written to a CSV file.

02

Rolling Buffer

Every second, the detection loop reads only the new bytes from the CSV file using a byte offset. New packets are appended to a rolling DataFrame. Packets older than 35 seconds are expired. This ensures the engine always has a full view of the recent traffic window.

03

Rule Evaluation

The detection engine runs all 8 rules against the buffer. Each rule filters by protocol, time window, and optionally TCP flags or destination ports. Packets are then grouped by source IP. If the count exceeds the threshold, an alert is generated.

04

Alert Logging

Each alert is saved to SQLite for querying and to a JSONL file for export. A 15-second cooldown prevents duplicate alerts from the same source IP and rule. Each alert gets a unique UUID event ID for traceability.

05

CLI & Dashboard

Users can view alerts in real time via the live dashboard at localhost:8050, or use the interactive CLI to run commands like view_logs, summary, export_logs, and show_rules.
